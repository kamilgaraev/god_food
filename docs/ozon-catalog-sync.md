# Прямое заполнение товаров из Excel

Скрипт `scripts/sync-ozon-catalog.php` создаёт и обновляет товары напрямую через WooCommerce, аналогично прежнему `sync-catalog.php`. Источник — исходный XLSX «Товары_11.08.2026_11.xlsx», лист «Товары». PHP должен иметь zip и SimpleXML (в Docker проекта они есть).

## Результат локального запуска

61 строка исходника: 25 обновлённых карточек и 36 новых опубликованных товаров. Две существующие позиции чиа сохранены, итого 63 товара. Все непустые поля исходника сохранены в метаданных `_theobroma_ozon_report`; основные идентификаторы записаны в поля интеграции. Масса нетто и количество указаны у 60 товаров. Габариты и вес брутто для доставки перенесены у 17 товаров с преобразованием в единицы магазина.

Новые товары опубликованы с наличием «нет в наличии»: в отчёте нет остатков именно интернет-магазина. Существующее наличие не меняется. Фото и описания существующих карточек сохраняются. Для новых используются названия/факты из файла; фото и состав не выдумываются. Утверждение «все товары полностью готовы к продаже» не делается.

Обычный молочный шоколад 30 г сопоставлен с `theobroma-30-date-powder` по разрешению владельца выбирать аналог; в карточке записана пометка. У набора 3×30 г в исходнике ошибочно указан брутто 38 г: исходное значение сохранено, в доставку оно не попадает. Объёмный вес Ozon не заменяет физический вес. Недостающие размеры не рассчитываются из объёма.

## Перенос на сервер в Docker

1. Сделайте резервную копию базы данных сервера. Скрипт заменяет цены на цены из отчёта и очищает старую акционную цену.
2. Загрузите `sync-ozon-catalog.php` и исходный Excel в одну папку на сервере (например, через SFTP). Переименуйте Excel в `ozon-catalog.xlsx`. Не нужно переносить локальную базу целиком.
3. Из папки проекта на сервере выполните (пути слева замените на папку загрузки):

```sh
docker compose cp /path/to/upload/sync-ozon-catalog.php wordpress:/tmp/sync-ozon-catalog.php
docker compose cp /path/to/upload/ozon-catalog.xlsx wordpress:/tmp/ozon-catalog.xlsx
# Проверка без записи:
docker compose exec -T wordpress php /tmp/sync-ozon-catalog.php /tmp/ozon-catalog.xlsx
# Создание/обновление:
docker compose exec -T wordpress php /tmp/sync-ozon-catalog.php /tmp/ozon-catalog.xlsx --apply
```

Повторный запуск сопоставляет товары по SKU сайта и Ozon ID/SKU и не создаёт дубликатов; при конфликте идентификаторов весь пакет отклоняется до записи. Во время записи используется поштучное сохранение WooCommerce: при сбое часть карточек может уже обновиться, после исправления причины запуск можно повторить. Не запускайте две копии синхронизации одновременно.

Если скрипт уже развёрнут в `scripts/` и каталог смонтирован как в Compose проекта, вместо `/tmp/sync-ozon-catalog.php` используйте `/opt/theobroma-scripts/sync-ozon-catalog.php`. Для хостинга без Docker:

```sh
WORDPRESS_ROOT=/path/to/wordpress php sync-ozon-catalog.php ozon-catalog.xlsx --apply
```

На пустом сайте сначала штатно разверните WordPress/WooCommerce и выполните прежний `scripts/sync-catalog.php`, чтобы получить 27 исходных карточек с фото. Затем запускайте новый скрипт. Если старый синхронизатор запускается позже, повторно выполните новый: старый записывает прежние цены.

## Проверка

```sh
php scripts/verify-ozon-catalog.php /path/to/ozon-catalog.xlsx
# В контейнере WordPress для проверки уже записанных данных:
php scripts/verify-ozon-catalog.php /path/to/ozon-catalog.xlsx --runtime
```

Локально обе проверки пройдены: все 61 позиции опубликованы, цены и архивные данные совпадают, габариты переведены в единицы магазина, повторный preview показывает 0 новых товаров. Перед заполнением создана копия `food/backups/theobroma-20260904-004851`.

Товары доступны в админке **Товары → Все товары** и на своих страницах. В существующей теме переключатель главного каталога пока содержит только старые пять групп; новые категории кофе, наборов, шоубоксов, крупной фасовки и упаковки созданы, но отдельные кнопки для них тема автоматически не добавляет.
