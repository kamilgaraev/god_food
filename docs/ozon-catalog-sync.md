# Прямое заполнение товаров одной командой

Из папки существующего проекта на сервере:

```bash
git fetch origin codex/fill-full-catalog && git show FETCH_HEAD:scripts/apply-ozon-catalog.sh | bash
```

Ничего отдельно загружать не нужно: исходный Excel включён в Git как `scripts/data/ozon-products-2026-08-11.xlsx`. Команда не переключает ветку сервера и не перезаписывает его рабочие файлы. Она берёт скрипты и Excel из полученного коммита, копирует их в работающий контейнер, проверяет данные, сохраняет дамп в `$HOME/theobroma-backups`, затем создаёт/обновляет товары и проверяет результат. Требуются Git, tar и работающие Docker Compose-сервисы `wordpress` и `db` этого проекта. Папку копий можно изменить через `CATALOG_BACKUP_DIR`. Не запускайте одновременно несколько синхронизаций.

## Данные и поведение

Исходник содержит 61 товар: локально обновлены 25 прежних карточек и созданы 36 новых. Две позиции чиа сохранены, всего 63 карточки. Создаваемые товары опубликованы с наличием «нет в наличии», поскольку остатки Ozon не являются остатками магазина. Наличие существующих товаров сохраняется.

Цены заменяются текущими ценами отчёта от 11.08.2026, старые акционные цены очищаются. SKU прежних карточек сохраняются, новые получают `ozon-<Ozon SKU>`. Артикулы клиента, Ozon Product ID/SKU и числовые EAN записываются в поля интеграции. OZN-штрихкоды не считаются EAN. Все столбцы исходника сохраняются в `_theobroma_ozon_report`.

Нетто/количество определены для 60 товаров; габариты и брутто для доставки перенесены для 17, с переводом в единицы магазина. У набора 3×30 г исходный брутто 38 г меньше нетто — сохранён только в исходных метаданных с пометкой, в доставку не перенесён. Недостающие размеры и состав не выдумываются. Молочный шоколад 30 г сопоставлен с карточкой на финиковой пудре как вероятный аналог по разрешению владельца, с пометкой.

Существующие фото/описания сохраняются. Новым карточкам ещё нужны реальные фото и полные описания. Переключатель основной страницы каталога пока содержит прежние пять групп; новые категории создаются в базе, но кнопки для них в теме автоматически не добавляются.

## Проверки и повторный запуск

`verify-ozon-catalog.php` проверяет 61 строку, уникальность SKU, массу наборов, конфликт брутто/нетто и сопоставление. В режиме `--runtime` сверяет товары в БД, цены, все исходные метаданные, перевод единиц веса и отсутствие новых товаров при повторном preview.

Перед записью всего пакета проверяются конфликты идентификаторов. Сохранение поштучное: при ошибке часть карточек может уже обновиться, после устранения причины можно повторить команду. Резервная копия создаётся до первого сохранения. После старого `sync-catalog.php` нужно повторить новый синхронизатор, поскольку старый скрипт записывает прежние цены.

Исходный каталог из 27 товаров уже должен быть развёрнут прежним `sync-catalog.php`, если нужны его оригинальные фотографии и тексты. На пустой базе новый скрипт создаст данные из Excel, но не восстановит контент старого каталога.
