# Прод и dev

Прод: `theobroma.one`, каталог `/opt/god-food-prod`, Compose project `theobroma-prod`.
Dev: `theobroma.uit-dev.ru`, каталог `/opt/god-food`, Compose project `god-food`.
Базы и Docker volumes независимы. Данные перенесены с технического сайта;
старый сайт и исходные volumes не удалялись.

## Запуск и обновление

На сервере использовать `sh scripts/site-compose.sh ps` и
`sh scripts/site-compose.sh up -d --wait`. Скрипт выбирает локальный
`compose.runtime.json`, который содержит реальные подключения, сети и лимиты.
Не запускать обычный `docker compose up`: репозиторный compose предназначен
для локальной разработки и не содержит серверной изоляции.

`compose.runtime.json` и `.runtime/` содержат секреты, исключены из Git.
Не копировать продовую базу поверх dev или наоборот при обычном деплое кода.
Образ `theobroma-wordpress:production-baseline-20260922` — локальный снимок
существующего runtime; не публиковать в registry: исходный контейнер содержал
переменные окружения с доступами.

## Защита dev

Nginx запрашивает Basic Auth. Доступы: `/opt/god-food/.runtime/dev-access.json`.
Dev подключён только к внутренней Docker-сети. MU-плагин
`theobroma-environment-safety.php` при `THEOBROMA_ENVIRONMENT=staging` отключает
cron, фоновые очереди, внешние WordPress HTTP-запросы и способы оплаты,
направляет письма в Mailpit, запрещает индексацию. Настройки интеграций сохранены.

Прод использует `THEOBROMA_ENVIRONMENT=production` и отдельную сеть с выходом
в интернет. Nginx проксирует его на `127.0.0.1:8081`.
Адрес dev upstream находится во внутренней сети: при пересоздании dev проверить
IP контейнера и `/etc/nginx/sites-available/god-food`.

## Уведомления интеграций

Старый URL с `?yookassa=callback` и точный путь
`/wp-json/theobroma-commerce/v1/cdek/webhook` на техническом домене
проксируются в прод, обходя Basic Auth. Это сохраняет ранее зарегистрированные
callback URL. Остальные запросы технического домена обслуживает защищённый dev.
Проверки подписи и содержимого уведомлений выполняют штатные обработчики.

## Резервная копия и DNS

Исходный снимок: `/opt/theobroma-backups/before-prod-20260921-230651`:
SQL, WordPress, исходный Compose/env и nginx. Не публиковать содержимое.
Сверка перед запуском: совпали основные таблицы, 16 заказов, 2 пользователя,
1498 файлов uploads и настройки интеграций. На проде затем обновлён OAuth Ozon.

Для основного домена A-записи `@` и `www` должны указывать на `201.24.124.12`.
SPF, DKIM и прочие почтовые записи сохраняются.
Сертификат `/etc/letsencrypt/live/theobroma.one/` выпущен через DNS-01,
затем renewal переведён на HTTP-01 webroot `/var/www/letsencrypt`.
`certbot reconfigure` прошёл тестовое продление; после обновления выполняется
`systemctl reload nginx`. `certbot.timer` включён.
REG.RU и Cloudflare DNS подтвердили новые A-записи 22.09.2026 (МСК).
Другие резолверы могут сохранять прежний IP до истечения TTL.

## Проверки переноса

- HTTPS с проверкой сертификата, редирект www, главная, каталог,
  корпоративная страница и ЛК проверены через новый сервер на 390/1440 px.
  Добавление товара в корзину и наличие полей оформления проверены в браузере.
  Dev без пароля возвращает 401, с паролем — 200 и noindex.
- SMTP переключён на официальный альтернативный TLS-порт `9587`:
  обычные 587, 465 и 2525 с сервера не соединяются.
  STARTTLS и авторизация проверены в самом WordPress через PHPMailer.
  Домен отправителя подтверждён в SMTP.BZ, SPF/DKIM/CNAME найдены.
  Тестовые письма в ходе переноса не отправлялись.
- Авторизация API ЮKassa/СДЭК проверена; Ozon refresh прошёл.
  Это не заменяет полный тест покупки и создания отправления.
