# Настройка внешних интеграций Theobroma

Код интеграций устанавливается выключенным и не показывает покупателю неподтверждённые способы доставки или оплаты.

## Яндекс.Метрика

1. Создать счётчик для боевого домена и получить числовой ID.
2. Открыть `Настройки → Аналитика Theobroma`, указать ID и нужные функции счётчика.
3. До cookie-consent внешний скрипт не загружается. После сохранения проверить запрос `mc.yandex.ru/metrika/tag.js`, визиты и цели в интерфейсе Метрики.
4. Вебвизор по умолчанию выключен; включать его только после согласования политики обработки данных.

Статические CSS/JS кэшируются браузером один месяц, изображения и шрифты — один год. На боевом хостинге full-page cache включается отдельно; из него исключаются `/cart/`, `/checkout/`, `/my-account/`, WooCommerce AJAX/REST и ответы при наличии cart/session cookies.

## ЮKassa

1. Подключить магазин в ЮKassa и завершить договор/идентификацию.
2. Установить официальный плагин версии `2.16.3` командой `bash scripts/install-required-plugins.sh`.
3. В WordPress открыть `WooCommerce → Настройки → Платежи → Онлайн-оплата` и пройти авторизацию ЮKassa.
4. Настроить НДС, систему налогообложения и чеки по фактическим данным организации.
5. Сначала выполнить тестовый платёж и возврат. Включать способ оплаты покупателям только после проверки изменения статусов заказа и чеков.

## СДЭК API v2

1. Получить в кабинете интеграции СДЭК `Account / Client ID` и `Secure password / Client secret`.
2. В WordPress открыть `WooCommerce → Интеграции` и указать Client ID, город и адрес отправителя.
3. Секрет предпочтительно определить в `wp-config.php`:

   ```php
   define('THEOBROMA_CDEK_CLIENT_SECRET', '...');
   ```

4. В СДЭК зарегистрировать webhook типа `ORDER_STATUS` на адрес, показанный в настройках интеграции: `/wp-json/theobroma-commerce/v1/cdek/webhook`.
5. Проверить реальный расчёт для ПВЗ и курьера, создание отправления только после оплаты и синхронизацию статуса. После этого включить СДЭК в настройках.

## Ozon Доставка

1. Магазин должен быть российским продавцом Ozon, работать по FBO и/или FBS и одновременно продавать на своей площадке.
2. В кабинете продавца открыть `Товары → Приложения → Ozon Доставка`, заполнить анкету и дождаться статуса «Подключено» (проверка может занять до пяти рабочих дней).
3. Создать частное приложение в `Настройки → Приложения и разрешения` со scope:
   - `Seller-api.ozon-logistics`;
   - `Seller-api.posting-fbo`;
   - `Seller-api.posting-fbs`;
   - `Seller-api.returns`;
   - `Seller-api.report`;
   - `Seller-api.product`.
4. Получить OAuth-токен частного приложения и предпочтительно определить его в `wp-config.php`:

   ```php
   define('THEOBROMA_OZON_ACCESS_TOKEN', '...');
   ```

5. В каждой карточке товара WooCommerce заполнить поле `Ozon SKU`; зарегистрировать соответствующие остатки на стороне Ozon.
   Страница `WooCommerce → Интеграции` автоматически сверяет весь опубликованный каталог и показывает количество и ID карточек без Ozon SKU. Ручное подтверждение остатков не заменяет эту проверку.
6. В `WooCommerce → Интеграции` отметить одобрение заявки и завершённое сопоставление товаров.
7. У Ozon Доставки нет sandbox. Провести полный цикл на согласованном номере сотрудника: `delivery/check` → выбор доставки → `delivery/checkout` → оплата → `order/create` → получение/отмена. До успешного теста способ доставки остаётся скрытым.
8. При неполном тесте сразу запросить отмену и дождаться подтверждённого статуса отмены; возврат денег выполнять только после подтверждения отмены Ozon.
9. `v2/order/create` вызывается только после подтверждения оплаты и только с результатом `v2/delivery/checkout`. Успех считается подтверждённым, когда ответ содержит непустой `order_number`; HTTP 200 без номера заказом не считается. Номера отправлений сохраняются из массива строк `postings`.

## Бонусная программа

- Один бонус равен одному рублю.
- После оплаты зарегистрированному покупателю начисляется 5% стоимости товарных позиций после скидок; доставка и её налог в базу не входят.
- На оформлении заказа можно списать не более 20% стоимости товарных позиций и не больше доступного баланса.
- До оплаты сумма резервируется. При успешной оплате резерв становится списанием, при `failed`/неоплаченной отмене возвращается.
- При полном или частичном возврате начисление и списание корректируются пропорционально возврату. Если начисленные ранее бонусы уже потрачены, баланс может стать отрицательным; новое списание блокируется до погашения долга.
- Все операции идемпотентны и хранятся в `${table_prefix}theobroma_loyalty_ledger`; баланс — в `${table_prefix}theobroma_loyalty_accounts`.

Для сверки сначала выгрузить заказ через WooCommerce REST API/1С вместе с meta:

- `_theobroma_bonus_reserved_kopecks`;
- `_theobroma_bonus_spent_kopecks`;
- `_theobroma_bonus_accrued_kopecks`;
- `_theobroma_bonus_reversed_kopecks`;
- `_theobroma_bonus_restored_kopecks`;
- `_theobroma_cdek_uuid`, `_theobroma_cdek_status`;
- `_theobroma_ozon_order_number`, `_theobroma_ozon_postings`.

Ручную корректировку баланса напрямую в таблицах не выполнять. Сначала сопоставить заказ, возвраты и ledger по `order_id`/`idempotency_key`, затем провести корректирующую операцию через сервис интеграции и повторить сверку. Перед восстановлением из резервной копии сохранить обе loyalty-таблицы и заказы WooCommerce одним согласованным снимком.
