# Матрица приёмки Theobroma

Финальный локальный регрессионный прогон выполнен 7 августа 2026 года на `http://localhost:8080`.

| Требование | Статус и доказательство |
| --- | --- |
| Избранное | Реализованы гостевое хранение и серверное хранение авторизованного пользователя. Пустое и заполненное состояния попарно проверены с оригиналом на 390/430/768/1440/1920/2048/2560/3840 px; mobile/tablet drawer и desktop drawer 560 px совпадают по геометрии. |
| Доступность | 104/104 маршрутных проверок на 390/1440 px: язык, title, единственный main, H1, skip-link, уникальные ID, alt, имена контролов и подписи полей. Клавиатурой проверены skip-link, mobile menu, account, пустые wishlist/cart и product modal: focus trap, Escape, возврат фокуса и видимый focus indicator. |
| WordPress + WooCommerce, контент и SEO | Пройден `scripts/verify-wordpress.php`: 27 товаров, 4 статьи, рецепты, юридические страницы, корпоративные подарки и SEO-описания. |
| Адаптивность | Все исходные публичные маршруты попарно сняты на 390/430/768/1440/1920/2048/2560/3840 px; локальные маршруты — на 390/768/1440/2560 px. Header, cookie, меню, account/cart/product states дополнительно проверены на всех восьми ширинах. Overflow не найден. На 2560/3840 сохранён согласованный cap header вместо дефекта исходной Tilda. |
| Товарная и корзинная модалки | Проверены открытие/закрытие, история URL, zoom, галерея, добавление, количество, удаление, пустая и заполненная корзина на 390/430/768/1440/1920/2048/2560/3840 px. Dynamic classic checkout теперь сохраняет нативный submit-handler WooCommerce; реальный `wc-ajax=checkout` и серверная валидация проходят. |
| Галерея и вариативные товары | Runtime-фикстура создаёт WooCommerce variable product с 9 изображениями и двумя вариантами с разными ценами/фото. `scripts/verify-product-capabilities.spec.js` подтверждает галерею, смену цены и изображения и добавление конкретной вариации в корзину на 390/768/1440 px, после чего удаляет фикстуру. |
| Личный кабинет и бонусы | Реальным входом проверены 7 экранов (dashboard, заказы, бонусы, адреса, billing, shipping, профиль) на 390/768/1440/2560 px: 28/28, шесть пунктов меню, без ошибок и overflow. |
| Медиа и кросс-продажи | 4 статьи содержат валидные связанные WooCommerce-товары; блок открывает существующую товарную модалку. Query-helper формирует по 3 похожие статьи той же рубрики, исключает текущую публикацию; browser-test проходит на 390/430/768/1440 px без overflow. |
| Корпоративные подарки | Реализована страница `/corporate-gifts/`, B2B-форма, сохранение заявки и уведомление через `wp_mail`. |
| SEO | `scripts/verify-seo-runtime.js` подтверждает реальные ответы `robots.txt`, sitemap страниц/статей/товаров, canonical, description/OG, Product и Article JSON-LD, noindex приватных commerce-экранов и redirect пустого checkout. Карта пользователей отключена; публичные товары, статьи, страницы, рецепты и категории остаются в sitemap. Unit-тесты 8/8 и WordPress SEO smoke проходят. |
| Антиспам | Все контактные формы используют nonce, honeypot и серверную задержку минимум 3 секунды. |
| HTTP-безопасность | Apache отдаёт `nosniff`, `SAMEORIGIN`, `strict-origin-when-cross-origin` и запрет неиспользуемых camera/microphone/geolocation; `scripts/verify-security-headers.js` проверяет публичные и приватные маршруты. HSTS включается конфигурацией только на HTTPS; для TLS termination его должен выставлять production reverse proxy. |
| Системные письма | SMTP-транспорт настраивается переменными среды. Локально Mailpit принял настоящее письмо WooCommerce покупателю; `scripts/verify-email-flow.php` подтвердил адресата, номер заказа и товар в теле письма. На production требуется SMTP-аккаунт домена. |
| Ozon Доставка | **Не готово к live-приёмке:** `0/27` внешних SKU, нет merchant approval/token и подтверждённого live-теста. Реализация корректно не предлагает доставку до выполнения этих условий. |
| СДЭК | **Не готово к live-приёмке:** необходимы договор, Client ID/secret, данные отправителя, тарифы и тестовый заказ. |
| ЮKassa / 54-ФЗ | **Не готово к live-приёмке:** нужны demo/live Shop ID и secret key, настройка уведомлений и согласованная схема фискализации. |
| Облачная 1С | **Не готово к реализации/приёмке:** отсутствуют согласованные протокол, доступы, формат обмена и правила бонусов/скидок. |
| Яндекс.Метрика | Настройка реализована отдельным плагином: ID и опции редактируются в админке, невалидный ID отключает вывод, загрузка происходит только после cookie-consent. **Сбор данных не включён:** требуется реальный ID счётчика. |
| Яндекс.Вебмастер | Токен подтверждения редактируется в «Настройки → SEO Theobroma»; пустое или невалидное значение не выводит meta tag. Рендеринг покрыт unit- и runtime-проверками. **Сайт не подтверждён во внешнем кабинете:** требуется реальный токен владельца. |
| Core Web Vitals | `scripts/audit-core-web-vitals.js` проверяет главную, каталог, товарную модалку и статью на desktop и эмулированном Fast 4G mobile. Пороговые значения: LCP ≤ 2,5 с, CLS ≤ 0,1, INP ≤ 200 мс, TTFB ≤ 800 мс. Финальный прогон: LCP 0,36–0,55 с desktop и 1,76–2,09 с mobile; CLS 0; измеренный INP до 24 мс; TTFB 0,21–0,42 с. |
| Кэширование | Для CSS/JS настроен browser cache на 1 месяц, для изображений/woff2 — на 1 год; динамический HTML не кэшируется. Full-page/server cache остаётся настройкой хостинга с обязательными исключениями cart/checkout/my-account и WooCommerce cookies. |
| Резервные копии | `scripts/backup-site.ps1` создаёт transactional MySQL dump, uploads archive, SHA-256 и manifest. `scripts/verify-backup-restore.ps1` реально восстановил dump в изолированную БД и подтвердил 27 товаров, 5 записей, 18 страниц, 1 пользователя и читаемый uploads-архив; временная БД удалена. **На production ещё нужны:** расписание, внешнее зашифрованное хранилище, retention и ежемесячный restore-test. |

AI-конструктор намеренно не реализован: по ТЗ он выделен в отдельный этап, а текущая задача прямо исключает его из реализации.
