# Настраиваемые формы заявок — дизайн

## Цель

Создать отдельный WordPress-плагин `theobroma-contact-forms`, который управляет полями и адресами получателей двух публичных форм: на главной странице и на странице «Сотрудничество». Корпоративная форма остаётся вне плагина.

## Поведение

- Для каждой формы независимо настраиваются поля «Имя», «Телефон», «E-mail» и «Комментарий».
- Для каждого поля доступны флаги «Показывать» и «Обязательное»; обязательное поле всегда считается показываемым.
- Для каждой формы задаётся отдельный e-mail получателя. Пустой или некорректный адрес заменяется административным e-mail WordPress.
- Значения по умолчанию для обеих форм: имя показывается, телефон показывается и обязателен, комментарий показывается, e-mail выключен.
- Публичная форма сохраняет nonce, согласие на обработку данных, honeypot и задержку антиспама.
- После успешной отправки заявка сохраняется в `contact_request` и отправляется через `wp_mail()` настроенному получателю.
- При отключённом плагине тема показывает безопасный fallback: имя, обязательный телефон и необязательный комментарий; письмо идёт на административный e-mail.

## Архитектура

Плагин содержит чистую модель `Settings`, рендерер `FieldRenderer`, проверку и подготовку уведомлений `Submission`, административную страницу `SettingsPage` и bootstrap `Plugin`. Bootstrap публикует небольшой набор глобальных функций интеграции, защищённых `function_exists`, чтобы тема не зависела от загрузки классов напрямую.

Шаблоны темы передают идентификатор `home` или `cooperation` и вызывают рендерер плагина. Обработчик темы получает ту же конфигурацию, санитизирует разрешённые поля, проверяет обязательность и отправляет письмо. Корпоративная ветка обработчика не использует API плагина.

## Безопасность и совместимость

- Настройки сохраняются через Settings API с `manage_options`, nonce `options.php` и `sanitize_callback`.
- Разрешены только известные идентификаторы форм и полей.
- E-mail проходит `sanitize_email()` и `is_email()`.
- Пользовательские данные санитизируются текущими WordPress-функциями до сохранения и отправки.
- Старые закэшированные формы продолжают обрабатываться: неизвестные или выключенные поля игнорируются.

## Проверка

- Unit-тесты модели настроек, обязательности, HTML полей и строк письма.
- Контрактный тест шаблонов для двух идентификаторов форм и корпоративной формы.
- PHP lint изменённых файлов, существующие проверки телефона и согласия.
