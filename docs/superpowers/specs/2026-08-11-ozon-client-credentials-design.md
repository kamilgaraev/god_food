# Автоматическая авторизация Ozon Доставки

## Цель

Администратор вводит только `Client ID` и `Secret` частного приложения Ozon. Плагин самостоятельно получает и кеширует OAuth access token. Ozon Доставка показывается в checkout только тогда, когда каждый товар или вариация в корзине имеет заполненный `Ozon SKU` и Ozon вернул подтверждённый расчёт.

## Настройки

В настройках Ozon остаются:

- `Client ID`;
- `Secret` с сохранением прежнего значения при отправке пустого поля;
- кнопка «Проверить подключение» и результат последней ручной проверки авторизации.

Удаляются ручное поле OAuth access token и флаги одобрения заявки, регистрации остатков, live-теста и общего включения. Секрет не возвращается в HTML после сохранения и не попадает в логи. Константы `THEOBROMA_OZON_CLIENT_ID` и `THEOBROMA_OZON_CLIENT_SECRET` имеют приоритет над значениями WordPress, чтобы production мог хранить секреты вне базы данных.

## Компоненты

### OzonAuthenticator

Получает access token по `Client ID` и `Secret` через официальный OAuth endpoint Ozon. Проверяет HTTP-статус, наличие непустого `access_token` и срок действия. Возвращает только валидный токен.

### OzonTokenStore

Интерфейс хранилища токена с операциями чтения, записи и удаления. WordPress-реализация хранит токен и время истечения в transient. Тестовая memory-реализация позволяет проверять кеширование без WordPress.

Токен считается просроченным немного раньше фактического срока, чтобы запрос не ушёл с истекающим credential. Изменение `Client ID` или `Secret` очищает кеш.

### OzonClient

Клиент получает `OzonAuthenticator`, а не готовую строку токена. Перед API-запросом он запрашивает актуальный токен и добавляет `Authorization: Bearer ...`.

При первом ответе `401` клиент очищает кеш, получает новый токен и повторяет запрос ровно один раз. Другие ошибки и повторный `401` пробрасываются как безопасный `ProviderException` без credential в контексте.

### Доступность доставки

Отдельная проверка проходит по фактическим позициям корзины. Для вариации сначала используется её собственный `Ozon SKU`; если он отсутствует, допускается SKU родительского товара. Если хотя бы для одной позиции SKU не найден, Ozon Доставка не предлагается всей корзине.

Глобальные ручные readiness-флаги больше не участвуют в расчёте. Наличие credential само по себе не создаёт тариф: метод добавляется только после успешного ответа расчёта Ozon с ценой, названием и payload для создания заказа.

## Поток данных

1. Администратор сохраняет `Client ID` и `Secret`; при их изменении кеш токена очищается.
2. Checkout собирает Ozon SKU всех позиций и прекращает расчёт, если список неполный.
3. `OzonClient` получает токен из кеша либо выполняет OAuth-запрос.
4. Плагин отправляет запрос расчёта доставки Ozon.
5. Подтверждённый ответ преобразуется в тариф WooCommerce и сохраняет необходимый payload в metadata тарифа.
6. После подтверждения оплаты сохранённый payload используется для создания заказа Ozon.

## Ошибки и наблюдаемость

Недоступность OAuth или API Ozon не ломает checkout: тариф Ozon не добавляется. В WooCommerce logger записываются код этапа, HTTP-статус и идентификатор заказа при его наличии. Токены, Client ID, Secret и полные provider-response с потенциальными персональными данными не логируются.

Ручная проверка подключения различает только необходимые состояния: реквизиты не заполнены, подключение работает, ошибка подключения. Открытие страницы настроек само по себе не вызывает Ozon API. Дополнительные проверки готовности не вводятся.

## Совместимость и миграция

Существующий `ozon_access_token` перестаёт использоваться после перехода. При сохранении новых реквизитов старое значение удаляется из настроек. До ввода `Client ID` и `Secret` Ozon Доставка остаётся скрытой.

Существующие Ozon SKU товаров и метаданные уже созданных заказов сохраняются без изменений.

## Проверки

- получение токена по `Client ID` и `Secret`;
- повторное использование токена из кеша;
- досрочное обновление истекающего токена;
- одно повторение API-запроса после `401`;
- отсутствие credential в исключениях и логах;
- сохранение прежнего Secret при пустом поле;
- очистка кеша после изменения реквизитов;
- скрытие Ozon для корзины хотя бы с одной позицией без SKU;
- поддержка SKU вариации и fallback на родительский товар;
- добавление тарифа только по подтверждённому ответу Ozon;
- создание заказа после оплаты с сохранённым checkout payload.

Реальные реквизиты и полный цикл проверяются только на стенде; unit-тесты используют recording transport и не обращаются к Ozon.
