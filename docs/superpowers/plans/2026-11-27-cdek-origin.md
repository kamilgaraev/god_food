# Сдача СДЭК в ПВЗ отправителя

Пользователь подтвердил MSK362 (Москва, Большая Очаковская, 19) как текущий пункт сдачи и разрешил настройку. Нужны согласованные расчёт и создание с shipment_point, выбор delivery_mode 3/4 и сохранение origin в подтверждённом расчёте и строке доставки заказа. Пустая настройка сохраняет прежний door-origin для существующих установок. Старые заказы используют сохранённую схему, новые корзины отклоняют расчёт от прежнего пункта. При смене пункта сбрасывается shipping cache WooCommerce. На проде сохраняются остальные настройки/секреты, существующие отправления не пересоздаются.

Проверки — unit-тесты склада/двери, сборка обеих сторон доставки, сохранение и смена настройки, инвалидирование подтверждённого расчёта, живой read-only calculator CDEK и штатная сборка заказа на dev. Сначала dev, затем точечная поставка на прод с приватной резервной копией и настройкой MSK362.

Пользователь промежуточно просил только склад-склад, затем подтвердил возможность курьерской доставки. Финальный объём сохраняет оба вида получения, никаких pickup-only ограничений не осталось.

Реальный API калькулятора требует from_location даже при shipment_point. Поэтому сервис сначала проверяет ПВЗ отправления через deliverypoints (is_reception), берёт его city_code и отправляет оба поля в калькулятор. В накладной используется shipment_point вместо from_location. Живой read-only расчёт принят; для тестового направления доступны 136 и 137. Специальные тарифы 357/358 фулфилмента и тарифы с таким названием исключены. 169 unit-тестов прошли. На dev выполнена quote→rate meta→WC shipping item→order payload проверка для обоих видов без реальных заказов.
